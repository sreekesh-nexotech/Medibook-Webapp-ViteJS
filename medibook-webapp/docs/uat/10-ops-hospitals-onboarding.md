### Faults found (NEW unless an existing blocker ID is cited)

- F1. "Onboarding Pipeline" button and the Pending-tab empty-state action are shown to finance/support, who lack `onboarding.view` and land on a ForbiddenScreen — `OpsHospitalsScreen.tsx:236-238,212-214` — confusing dead end for 2 of 6 roles — frontend: wrap in `CanOps perm="onboarding.view"`.
- F2. Empty-registry action "Onboard a hospital" is not gated by `hospitals.add` — `OpsHospitalsScreen.tsx:212-214` — non-writer roles fill a long form and get 403 — frontend.
- F3. Onboarding server errors for numbering and first admin never reach a field: nested errors are dropped by `toFieldErrors`, and the backend keys format/prefix errors as bare `format` / `prefix` (no series) — `toFailure.ts:56-65`, `OnboardHospitalModal.tsx:141-153`, `be:hospitals/services/numbering.py:51-68,257-273` — a tester with a clashing prefix or a bad token sees only "Some fields are invalid." — both (frontend: flatten dotted keys + map `prefix`/`format`; backend: key as `numbering.<kind>.<field>`).
- F4. Client-side format validation is weaker than the server's (no unknown-token, single-SEQ, SEQ:n range, brace, or booking `{PREFIX}` checks) — `OnboardHospitalModal.tsx:103-107` vs `numbering.py:51-68,260-263` — frontend: mirror `validate_format`.
- F5. Hospital phone at onboarding accepts only Indian mobiles; landlines are impossible although the backend and the Edit modal take any E.164 — `OnboardHospitalModal.tsx:115,163`, `validate.ts:46-54` — frontend.
- F6. Plan and Bookings/Mo columns are permanent "—" placeholders — `OpsHospitalsScreen.tsx:303,308` — testers will read them as missing data — backend list fields (see R1) or drop the columns.
- F7. Status filter stays set (and counted as "filters") while hidden on the Pending tab — `OpsHospitalsScreen.tsx:106-111,163,258` — misleading "No results match your filters" — frontend.

### Needs API integration or rework

- R1. Plan / Bookings-per-month columns — currently UI-only "—" — need `plan_code`/`plan_name` and a 30-day booking count on `GET /platform/hospitals` rows (NEW).
- R2. Registry filters — city / `app_visibility` are supported by the backend (`platform_hospital_list.py:28-31`) but not offered; there is no state filter on either side; list row already carries `commission_bp`, `go_live_at`, `app_visibility`, `online_booking_enabled` but no column shows them.
- R3. Timezone — not collected or shown anywhere; add a select (backend already validates `timezone`).
