### Faults found (NEW unless an existing blocker ID is cited)

- F1. Helper copy promises a separate permission for patient-account detail and an audit row per detail view; neither exists — evidence `src/features/ops-users/presentation/screens/OpsUsersScreen.tsx:295-299`, `medibook/platform/views/users_detail.py:12`, `medibook/core/api.py:100-107` — testers and compliance get a false assurance — fix: backend logs platform reads of `/users/{id}` (see Patient Account F3, R4) or frontend removes the sentence.
- F2. An owner can change their own role (or the last owner's) to one without `staff.*`, losing access to this screen with nobody left to restore it — evidence `OpsUsersScreen.tsx:235-244` (Edit shown on own row), `medibook/platform/services/staff_admin.py:80-87` (no guard; deactivate has one at :91-92) — fix: both (hide Edit on own row; backend refuses self role change and demoting the last `owner`).
- F3. Search is client-side over the first ≤100 rows; no role/status filter and no pager although the backend has them — evidence `OpsUsersScreen.tsx:90-97,287-291`, `opsUsers.api.ts:24-27` — low impact at year-one team size — fix: frontend (send `status`, `role_id`, `page`; keep name search client-side or add it to backend `q`).
- F4. Reactivating a member who was deactivated while still `invited` makes them `active` with no password; there is no resend-invite action (they must use Forgot password, which accepts invited/active platform staff, `medibook/accounts/services/staff_auth.py:153-154`) — evidence `staff_admin.py:110-117` — fix: backend (restore the previous status, add a resend endpoint).

### Needs API integration or rework

- R1. ### Faults found (NEW unless an existing blocker ID is cited)

- F1. The convenience-fee GST cannot be changed from the console: pricing uses `platform_settings.convenience_fee_tax_rate_bp`, which the form does not show, while the Tax Rates card offers a "Convenience Fee" rate (seeded `GST_18`) that pricing never reads — evidence `medibook/catalog/services/fees.py:278-286`, `OpsSettingsForm.tsx:29-34` — an ops user edits GST_18 and nothing changes — fix: frontend (add the field to the form) and backend (drive the convenience-fee tax from the `tax_rates` row, or refuse `applies_to=convenience_fee` on platform rates).
- F2. Tax-rate Code is editable in Edit mode but immutable on the server (400) — evidence `OpsSettingsTaxRateModal.tsx:163-165`, `medibook/platform/services/config_crud.py:131,215-219` — fix: frontend (read-only Code when editing).
- F3. `review_moderation_required` defaults to true and there is no moderation screen, so every patient review stays `pending` and is never published — evidence `medibook/platform/models/platform_settings.py:43`, `medibook/appointments/services/patient_review.py:28,38`; no frontend call to `/platform/reviews` — fix: frontend (Reviews moderation screen on `notifications.edit`, and/or the setting in this form).
- F4. Hospitals can raise support tickets from the web app (`src/features/help/infrastructure/data-sources/remote/help.api.ts:9`) and patients from the mobile app, but the console has no screen to read or answer them — evidence: no frontend call to `/platform/support/tickets*` — fix: frontend (Support screen on `support.*`; the support role has nothing else to do in the console).
- F5. Roles without `settings.view` (finance, support, compliance) call GET /settings on every console load (403) and always idle out at 15 minutes regardless of the platform setting — evidence `src/app/layouts/OpsShell.tsx:58,109` — fix: backend exposes `session_timeout_min` on `/platform/me` (NEW, platform side of SEC-01-B); frontend stops calling `/settings` without the permission.
- F6. 22 of 26 settings fields (trial/grace days, quiet hours, reminder offsets, OTP and lockout limits, upload cap, DSR cooling-off, review moderation, app versions, platform address, convenience-fee tax) have no UI — evidence coverage table — fix: frontend.
