# Flutter patient app — booking & payment path — UAT audit

> Appendix to [`docs/UAT_REPORT_2026-10-07.md`](../UAT_REPORT_2026-10-07.md). Static, code-level
> audit of web app commit `1ade3ae` against backend commit `b85a87b`; nothing here was run against a live
> backend. Paths under `src/` are in this repository (`medibook-webapp/`); paths under `medibook/` are in the
> Django backend repository; Flutter paths are under `lib/`. **NEW** marks a gap that is not yet logged in
> [`docs/BACKEND_BLOCKERS.md`](../BACKEND_BLOCKERS.md); other IDs (CORE-07, APPT-01, …) refer to that file.
> Status values: OK (wired to an existing endpoint with a matching contract), UI-only (local state only),
> Partial (wired, with a gap a tester will hit), Broken (a real fault), Blocked-backend (the backend lacks
> what the screen needs), Disabled (switched off on purpose, with an explanation), not built (the backend
> has it, the screen does not).

**Verdict: this Flutter build CANNOT make a booking against the backend — or any other API call. Every booking/payment screen runs on in-memory seed data; there is no HTTP client in the app at all. Real online bookings for the web-app UAT must be created with curl/Postman (Procedure below).**

Base URL: staging per round-2 doc `https://62.171.151.149:8443` (self-signed → `curl -k`, R-3); local stack default `https://localhost:8443` (`postman_export --base-url`). ### Step 3 — availability and a slot

- `GET /api/v1/patient/doctors/{doctor_id}/availability?from=YYYY-MM-DD&to=YYYY-MM-DD` (≤ 62 days; without `to` it stops one day short of the window — SLOT-01) → `{timezone, dates[{date, sessions[{session_id,session_code,label,state: available|full|closed,starts_at,ends_at}]}]}`.
- `GET /api/v1/patient/doctors/{doctor_id}/slots?date=YYYY-MM-DD` → `sessions[].slots[{id,starts_at,ends_at,state}]`; take an `id` with `state: "available"` → `slot_id`. Times are UTC; dates are hospital-local. Both responses are cached ≤ 30 s, so a just-taken slot can still look available (booking then answers `409 SLOT_UNAVAILABLE`). For the desk UAT ("online arrival to check in") pick a slot **later today**.

### Step 4 — the person, and the fee quote

- `GET /api/v1/patient/me/persons` → `results[]{id,is_self,first_name,last_name,relation,…}`; self row first → `person_id`.
- Fee quote is **GET, not POST**: `GET /api/v1/patient/fee-quotes?doctor_id={doctor_id}&person_id={person_id}[&coupon_code=CODE]` → `{consultation_fee_paise, service_fee_paise, discount_paise, convenience_fee_paise, tax_paise, tax_lines[], total_paise, is_follow_up, regular_consultation_fee_paise, follow_up_fee_paise, coupon: {code,valid:true}|{valid:false,reason}|null, lines[{line,description,supplier,amount_paise,tax_code,tax_rate_bp,tax_paise,tax_inclusive}], quoted_for_date}` (`catalog/views/patient_fee_quote.py`, `catalog/services/patient_fee_quote.py:65-117`). Informational: the booking re-quotes on the slot date and that snapshot is authoritative.

### Step 5 — book (this IS the hold; there is no hold endpoint)

`POST /api/v1/patient/appointments` headers `Idempotency-Key: <new uuid>` (required), `Content-Type: application/json`; body `{"slot_id":"…","person_id":"…"}` (+ optional `"coupon_code"`, `"patient_notes"`) (`appointments/serializers/patient_book_serializer.py`).
→ `201 {appointment:{id, booking_ref, status:"pending_payment", source:"online", token_no, token_label, token_source:"online", booking_deadline_at, payment_status:"pending", total_paise, hospital{…,timezone}, doctor{…}, …}, payment_order:{id, appointment_id, amount_paise, currency, channel:"online", gateway:"razorpay", gateway_order_id, status:"created", attempts:1, expires_at, key_id, created_at}}` (`appointments/views/patient_appointment_list.py:74-95`, `payments/serializers/payment_order_serializer.py`). `booking_deadline_at` = now + `hold_timeout_seconds` (default 300). In fake mode `gateway_order_id` is `order_fake…` and `key_id` is `""`.
Errors: `400 VALIDATION_ERROR` (incl. missing `Idempotency-Key`), `404 NOT_FOUND "Unknown person."`, `409 SLOT_UNAVAILABLE` (slot not open/past, doctor or session not bookable, hospital hidden / read-only / `online_booking_enabled=false`), `409 TOKEN_RANGE_EXHAUSTED`, `409 COUPON_INVALID|COUPON_EXPIRED|COUPON_MIN_ORDER|COUPON_USAGE_CAP`, `409 IDEMPOTENCY_CONFLICT` (same key, different body; same key + same body replays the stored 201) (`appointments/services/booking.py:30-157`, `core/idempotency.py`).

### Step 6 — pay (capture). Read this before UAT day: on a `PROVIDERS_MODE=fake` server the checkout `verify` route cannot capture

- **Why `verify` fails in fake mode:** `POST /payments/orders/{order_id}/verify {razorpay_payment_id, razorpay_signature}` first checks `HMAC_SHA256(RAZORPAY_KEY_SECRET, "{gateway_order_id}|{payment_id}")` (computable if you know the secret), then calls `FakeRazorpay.fetch_payment(payment_id)`, which reads an **in-process class dict** filled only by `FakeRazorpay.pay()`. No HTTP route calls `pay()`; only the seeder and tests do (`integrations/razorpay/client.py:28-32,81-123`, `payments/services/online.py:215-227`, `devseed/timeline.py:224-245`). Any id from outside → `KeyError` → unhandled → **HTTP 500** (`core/exceptions.py:99`). Static reading, not executed.
- **Option A — dev-only capture through the signed webhook (works in fake mode, no Razorpay account):** needs a **non-empty** `RAZORPAY_WEBHOOK_SECRET` on the server, known to the tester, and the `webhooks` Celery worker running. With an empty secret every webhook is rejected `400 PAYMENT_SIGNATURE_INVALID` (`client.py:35-41`), so the Postman folder note "dev secrets are usually empty strings" can never pass. Within the 5-minute deadline:
  ```sh
  BODY='{"event":"payment.captured","payload":{"payment":{"entity":{"id":"pay_uat_0001","order_id":"<payment_order.gateway_order_id>","amount":<payment_order.amount_paise>,"method":"upi"}}}}'
  SIG=$(printf '%s' "$BODY" | openssl dgst -sha256 -hmac "$RAZORPAY_WEBHOOK_SECRET" | sed 's/^.* //')
  curl -k -X POST "$BASE/webhooks/razorpay" -H 'Content-Type: application/json' \
       -H "X-Razorpay-Signature: $SIG" -H "X-Razorpay-Event-Id: evt_uat_0001" --data-binary "$BODY"
  ```
  → `200 {"status":"accepted"}` (`duplicate` for a reused event id). The worker runs `online.capture()` with the payload's amount/method and **no gateway call**: order `paid`, appointment `scheduled` (or `pending_approval` where `online_requires_approval`), slot `booked`, receipt issued, ledger rows, `payment.captured` + `appointment.confirmed` outbox events (`webhooks/views/razorpay_webhook.py`, `webhooks/services/process.py:68-100`, `payments/services/online.py:81-212`). Mount is `/webhooks/razorpay`, not `/api/v1/webhook/…`. `amount` must equal `payment_order.amount_paise`, and capture must happen before `booking_deadline_at` and before the 60 s sweeper cancels the booking; otherwise the money is auto-refunded (`payment_after_deadline` / `amount_mismatch`, `online.py:120-145`). If `RAZORPAY_WEBHOOK_IPS` is set, the tester's IP must be on it. Use new `pay_…`/`evt_…` ids per booking.
- **Option B — server shell (ops only):** `DB_ROLE=owner python manage.py shell`, then what the seeder does: `receive.record("razorpay", event_id=…, event_type="payment.captured", payload=BODY)` inside `transaction.atomic()`, then `process.process(<webhook_event pk>)`. No signature is checked at this layer (`devseed/timeline.py:248-252`). Owner role is needed because `webhook_events` is append-only for the app role (`webhooks/services/process.py:3-4`).
- **Option C — real Razorpay test mode:** `PROVIDERS_LIVE=razorpay` + test `RAZORPAY_KEY_ID/_KEY_SECRET` (round-2 R-2). The booking then returns a real `order_…` and `key_id=rzp_test_…`; a tester completes Razorpay Checkout (any checkout.js page with `key`, `order_id`, `amount`) with a test instrument, then `POST /api/v1/patient/payments/orders/{payment_order.id}/verify` + `Idempotency-Key` body `{"razorpay_payment_id":"pay_…","razorpay_signature":"…"}` → `200 {status, order, payment, appointment}`; `400 PAYMENT_SIGNATURE_INVALID` otherwise (`payments/views/patient_order_verify.py`). `verify` also accepts gateway status `authorized` as paid (`online.py:223-226`) and never calls Razorpay's capture API, so the test account must have **auto-capture** on. Not verified (no keys).
- **Option D — no API at all:** a fresh `manage.py seed_demo --reset` books and pays ~9 upcoming online appointments per live hospital over the next 14 days (in-process fake checkout), plus one live unpaid hold (`devseed/timeline.py:946-968`). It refuses unless `ENVIRONMENT ∈ {dev, local, development}`, `PROVIDERS_MODE=fake` and owner role (`devseed/guards.py:10-31`), and `--reset` wipes all non-reference data.
- Failed attempt / retry: `POST /api/v1/patient/payments/orders/{order_id}/retry` + `Idempotency-Key` → `201` NEW order (old open orders → `cancelled`), same `expires_at`; `409 PAYMENT_ALREADY_CAPTURED`; `409 APPOINTMENT_NOT_ACTIONABLE` once the window closed (`payments/services/online.py:47-69`).

### Step 7 — verify the booking

`GET /api/v1/patient/appointments/{appointment_id}` → expect `status:"scheduled"` (`pending_approval` at an approval hospital, e.g. seeded Sahyadri), `payment_status:"paid"`, `token_label`, `token_source:"online"`, `receipt:{receipt_no,issued_at}`, `refunds:[]`, `actions:{can_cancel,cancel_blocked_reason,can_retry_payment,can_review}`, `payment_order` (`appointments/views/patient_appointment_detail.py`). Extras: `GET …/token-card` (`booking_ref, token_label, qr_payload, …`), `GET …/receipt`, `GET …/queue`. **`{SRC}` marker:** seeded hospitals use the format `{SRC}{SEQ:3}` → online `A001`, desk `W001` (`devseed/hospitals.py:334-339`). A hospital onboarded through the console keeps the default `{PREFIX}-{SEQ:3}` → `T-001` for **both** channels (`tokens/models/token_policy.py:35-41`), so before the queue UAT its admin must `PUT /api/v1/hospital/token-policy` (If-Match, `hospital_settings.edit`) with a format containing `{SRC}`. A changed format applies to new tokens only.

### Step 8 — optional: cancel to create an online refund for the desk UAT

`GET /api/v1/patient/appointments/{id}/cancellation-preview` → `{allowed, reason, cutoff_at, before_cutoff, refund_bp, refund_paise, non_refundable_paise, includes_convenience_fee}` (defaults: cut-off 4 h, 100 % before, 0 % after, `hospitals/models/hospital_settings.py:30-32`). Then `POST /api/v1/patient/appointments/{id}/cancel` + `Idempotency-Key`, body `{"reason":"UAT refund"}` → `200 {appointment:{status:"cancelled",cancelled_by:"patient",…}, refunds:[{id,payment_id,amount_paise,reason:"patient_cancellation",status:"requested",requested_at,processed_at}]}`; the gateway refund goes through the outbox to the payments queue (`payments/services/refunds.py:62-81,191-199`; in fake mode `FakeRazorpay.refund` answers `processed`; final row status not verified). Errors: `409 TOKEN_ALREADY_CALLED`, `409 TOKEN_CANCEL_WINDOW_CLOSED`, `409 APPOINTMENT_NOT_ACTIONABLE` (past start or not cancellable), `409 CANCELLATION_WINDOW_CLOSED`. An unpaid (`pending_payment`) booking can also be cancelled: no refund, and its coupon is returned. For a hospital-side refund the desk cancels instead (always 100 %, Q11). Leave the booking uncancelled if the desk must check it in.

UAT shortcut — "the hospital appears in the patient app after go-live" can be checked without the app: `GET /api/v1/patient/hospitals?q=<name>` needs no token (`anonymous_ok`, `hospitals/views/patient_hospital_list.py:30-35`). It is listed once `status=active` + `app_visibility=visible` + not read-only; `online_booking_enabled` must also be true to book (CORE-03-B).
