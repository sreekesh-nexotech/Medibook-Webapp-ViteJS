> Appendix to [`docs/UAT_REPORT_2026-10-07.md`](../UAT_REPORT_2026-10-07.md). Static, code-level
> audit of web app commit `1ade3ae` against backend commit `b85a87b`; nothing here was run against a live
> backend. Paths under `src/` are in this repository (`medibook-webapp/`); paths under `medibook/` are in the
> Django backend repository; Flutter paths are under `lib/`. **NEW** marks a gap that is not yet logged in
> [`docs/BACKEND_BLOCKERS.md`](../BACKEND_BLOCKERS.md); other IDs (CORE-07, APPT-01, …) refer to that file.
> Status values: OK (wired to an existing endpoint with a matching contract), UI-only (local state only),
> Partial (wired, with a gap a tester will hit), Broken (a real fault), Blocked-backend (the backend lacks
> what the screen needs), Disabled (switched off on purpose, with an explanation), not built (the backend
> has it, the screen does not).

Frontend: this repository (paths below start at `src/`).
Backend: the Django repository (paths start at `medibook/`, prefixed `be:`).
Seeded roles (`be: core/seeds/v1.py:69-120`): only **admin** holds `hospital_settings.*`,
`display_devices.*` and `billing_settlements.edit`; accountant has `billing_settlements.view/edit` but no
`hospital_settings.view`, so cannot reach any of these screens. All three routes sit behind
`RequireAdmin` → `RequirePermission perm="Hospital Settings.view"` (`app/router/RequireAdmin.tsx:18-24`,
`app/layouts/hospital-nav.ts:99-103`). Every write button checks `Hospital Settings.add/edit/del`, which
matches each backend view's per-method code (POST=add, PATCH/PUT=edit, DELETE=del) unless noted.

### Faults found (NEW unless an existing blocker ID is cited)

- F1. Map pin writes Bengaluru coordinates for every hospital (hard-coded 0.14° box at 12.84 N / 77.54 E; real coordinates outside the box clamp to the edge) — `SettingsEditor.tsx:148-154, 768-813` — a hospital in any other city that clicks the map saves a wrong location that patients use for directions — frontend: drop the fake map or use a real geocoder/map tile; keep typed lat/lng.
- F2. Token scheme option "Per-department prefix (C-001)" and its preview are fabricated: scope only partitions the sequence; the label stays `{PREFIX}-{SEQ:3}` = `T-001` in every department (two departments both call "T-001") — `settings.rules.ts:43-46, 193-198`; `be: tokens/models/token_policy.py:34-39` — tester selects it, next day sees T-001 not C-001; display screens show duplicate labels — frontend: preview from the policy's real `format`/`prefix` (and offer `{DEPT}` in format) or relabel the option "Separate count per department"; backend: none.
- F3. Token scheme hint pushes admins off the O-01 default ("the patient app expects the hospital-wide T-001 series" whenever scope = doctor, which is the seeded default) — `SettingsEditor.tsx:1095-1103`; `be: tokens/models/token_policy.py:34` — contradicts O-01 default; flag to product — frontend copy.
- F4. A pending token-scope change cannot be cancelled: the select starts at the in-force scope, so choosing it again is "not dirty" and Save stays disabled (backend cancels a pending change when the in-force value is sent) — `SettingsEditor.tsx:337, 541`; `be: tokens/services/policy_settings.py:157-163` — frontend: show the pending scope in the draft or add "Cancel scheduled change".
- F5. "Default consultation duration" claims no hospital default is stored, but `expected_consult_minutes` (Q29, 1–240) exists, is returned by `GET /settings`, and is already parsed — `SettingsEditor.tsx:1020-1025`, `settings.response.ts:91, 105` — the queue's long-call flag and wait estimates use it (TOK-01) yet the admin cannot set it — frontend: make the row editable.
- F6. "Auto mark No-show after" advertises a removed feature as "not yet available" (automatic no-show is removed, Q27/Q87); the real `no_show_call_attempts` setting has no control — `SettingsEditor.tsx:1087-1089` — frontend: replace with "Offer No-show after N skips" bound to `no_show_call_attempts`.
- F7. Cancellation rule copy hard-codes a 0% late refund ("later cancellations fall outside the refund window") and the refund tiers are not editable; the server's own `derived.cancellation_example` is parsed and dropped — `SettingsEditor.tsx:1076-1086`, `settings.response.ts:79, 109` — wrong text if a hospital's `refund_after_cutoff_bp` > 0 — frontend: show `derived.cancellation_example`, add the three refund fields.
- F8. "Validity (days)" hint says a follow-up "is not charged again"; the fee engine charges the doctor's `follow_up_fee_paise` (or the full fee when unset) — `SettingsEditor.tsx:1175-1178`; `be: catalog/services/fees.py:204-208` — misinforms admins about patient charges (see APPT-05) — frontend copy.
- F9. Scheduling-horizon hint computes its own end date one day earlier (`today+N−1`, browser time zone) instead of `derived.booking_window_end_date` — `SettingsEditor.tsx:528-531` — the same inconsistency SLOT-01 fixed on Slots & Availability, still present here — frontend: use the derived date (backend SLOT-01 still applies).
- F10. ### Faults found (NEW unless an existing blocker ID is cited)

- S-F1. Editing a hospital-wide service (`department_id = null`) silently moves it to the first department: the modal pre-selects `departments[0]` and makes Department mandatory, so any save (e.g. a price change) rewrites the department; hospital-wide services also cannot be created — `ServiceModal.tsx:35-36, 76`; `be: catalog/serializers/service_serializer.py:9` (null allowed) — data corruption; coupon/department filters then treat it differently — frontend: add a "Hospital-wide (all departments)" option and keep null.
- S-F2. Deleting a tax rate keeps charging it: `DELETE /tax-rates/{id}` soft-deletes the row, services keep `tax_rate_id`, and the fee engine reads `service.tax_rate` through Django's base manager (no `base_manager_name`, so soft-deleted rows are returned) — `be: catalog/services/tax_rates.py:66-74`, `catalog/services/fees.py:258`, `core/models/base.py:134`. The UI then shows those services as "tax exempt"/"Exempt" (`ServicesPricingScreen.tsx:260-261, 734-736, 1073`), the mutation comment says they "become exempt" (`services.mutations.ts:75`) and the confirm says nothing new can be billed — receipts will carry a tax the screen says is not there (related to SVC-01, distinct cause) — backend: refuse deleting a rate in use (list services) or clear the FK; frontend: until then show "deleted rate, still charged" and warn in the confirm.
- S-F3. Service-scoped coupons are unredeemable and the flat-value ceiling is wrong: coupons only apply to patient (online) bookings, which never carry a service (`be: appointments/services/booking.py:80-89`), and `validate_coupon` requires a scope match (`be: catalog/services/fees.py:169-175`); desk bookings never pass a coupon (`booking.py:248-257`). The modal still offers service scopes and caps a flat coupon at "the cheapest applicable service" although the discount base is the consultation fee (`CouponModal.tsx:39-54, 137-143, 197, 374-385`) — admins create codes that always answer `COUPON_INVALID`, or are blocked from valid flat values — product + both: either allow a service on online bookings / coupons at the desk, or drop service scopes and base the ceiling/preview on consultation fees.
- S-F4. "Online bookings only" copy claims the front desk can apply a code when the switch is off; no desk flow accepts a coupon (backend walk-in serializers have no `coupon_code`; `booking.py:248-257`; the web app's New Appointment has none) so the switch does nothing; new coupons default to off while the model default is on (`be: catalog/models/coupon.py:34`) — `CouponModal.tsx:159, 341-354`; empty state "the desk or the patient app can apply" `ServicesPricingScreen.tsx:595` — frontend copy now; backend if desk coupons are wanted.
- S-F5. Hidden codes and swallowed field errors: service and tax-rate `code` is derived from the name (`services.api.ts:42-44, 89, 137`), so two services/rates with the same name (two "GST" rates, "ECG" in two departments) or a non-Latin name (empty code) fail; coupon duplicates fail too; all three modals show only the envelope message "Some fields are invalid." (`ServicesPricingScreen.tsx:378-387`; `be: core/errors.py:9`) with no highlighted field — admin cannot tell what to change — frontend: make code editable/auto-suffixed, map `fieldErrors` (code, value, valid_to, scopes) into the modals.
- S-F6. Tax "Applies to: Consultations / Services & consultations" lets a hospital tax every consultation — a hospital rate outranks the platform default in `_tax_rate` (`be: catalog/services/fees.py:92-103, 246`) — overriding the O-04 default (consultation exempt) without warning; previews only ever price a service — `TaxModal.tsx:147-162`, `services.labels.ts:16-20` — flag O-04 to product; frontend: warn (or hide) until decided.
- S-F7. Pause/Resume and Edit of a coupon re-send its whole scope list; a scope pointing to a since-deleted service/department is rejected ("Unknown service/department") so the coupon can no longer be toggled; chips show raw UUIDs — `ServicesPricingScreen.tsx:122-138`, `CouponModal.tsx:402, 417`; `be: catalog/services/coupons.py:52-68`, `medical_services.py:82-87` (delete leaves scope rows) — frontend: send only `is_active` on toggle and drop unknown ids; backend: remove scope rows when a service/department is deleted.
- S-F8. Copy promises patient-facing services that do not exist: "Shown to patients in the Medibook app" (description), "procedures and tests patients can book" (empty state) — no patient endpoint lists services and patient bookings carry none; desk booking of services is APPT-06 — `ServiceModal.tsx:213`, `ServicesPricingScreen.tsx:569` — frontend copy (backend APPT-06).
- S-F9. Minor validation gaps: service price must be > 0 (API allows ₹0), whole rupees only; duration has no client max (server 1–1440 → generic error); percent coupons whole % only — `ServiceModal.tsx:34-39, 167, 183`, `CouponModal.tsx:261` — frontend.
- S-F10. Existing SVC-01 confirmed: switching a rate off does not stop it being charged; the screen's "still charged" labels are correct — no new action.
