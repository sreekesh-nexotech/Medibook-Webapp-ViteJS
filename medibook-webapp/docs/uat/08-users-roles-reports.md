> audit of web app commit `1ade3ae` against backend commit `b85a87b`; nothing here was run against a live
> backend. Paths under `src/` are in this repository (`medibook-webapp/`); paths under `medibook/` are in the

> Status values: OK (wired to an existing endpoint with a matching contract), UI-only (local state only),

Evidence prefixes: `web:` is the web app (`medibook-webapp/`), `api:` is the backend's `medibook/` package. Bare file names are unique under `web:src/features/users-roles/` or `web:src/features/reports/`. Static, code-level audit (nothing run against a backend).

## Screens covered

- UsersRolesScreen — route `/:role/users` — file `web:src/features/users-roles/presentation/screens/UsersRolesScreen.tsx` — gate: `RequireAdmin`, which is **no longer an admin-role check**: it resolves the view's module and requires `Users & Roles.view` (`web:src/app/router/RequireAdmin.tsx:18-25`, `web:src/app/layouts/hospital-nav.ts:100`); sidebar entry shown by `canViewModule` (`web:src/app/layouts/HospitalSidebar.tsx:51-57`). Backend: GET staff/roles/preview `users_roles.view`, PATCH/actions/role grid `users_roles.edit`, invitations list+create+resend+revoke `users_roles.add`, `/permissions` any member (`api:rbac/views/*.py`). Seed: only **admin** holds any `users_roles.*` (`api:core/seeds/v1.py:71-113`). Three tabs: Users, Roles & Permissions, Access Preview. **No Counters tab** — counters are only read (`GET /counters`) to name/assign a staff member's default counter.
- ReportsScreen — route `/:role/reports` — file `web:src/features/reports/presentation/screens/ReportsScreen.tsx` — gate: `RequireAdmin` → `Reports.view` (same mechanism). **The accountant is NOT locked out**: accountants land on the `/receptionist/*` shell (`web:src/features/auth/application/store/auth.roles.ts:16-18`), the sidebar and `HospitalShell` gate module views by permission only (`HospitalSidebar.tsx:51-57`, `web:src/app/layouts/HospitalShell.tsx:75`), the seed gives the accountant `reports.view` (`api:core/seeds/v1.py:97`) and all three backend report views require exactly `reports.view` (`api:reports/views/hospital_report_list.py:12`, `hospital_report_detail.py:12`, `hospital_report_export.py:14`). The UAT expectation (accountant runs reports) holds, except doctor/department filter options (F12). The stale `roles: ['admin']` on the Reports nav item (`hospital-nav.ts:61`) now only feeds the Access Preview, where it produces wrong information (F1).
- ReportDownloadScreen — route `/reports/downloads/:fileId` (emailed link, outside the shells) — file `web:src/features/reports/presentation/screens/ReportDownloadScreen.tsx` — gate: `ReportDownloadGuard` (`web:src/app/router/ReportDownloadGuard.tsx:37-76`): signed-in hospital session only; no permission check. Backend email link `{FRONTEND_HOSPITAL_URL}/reports/downloads/{file_id}` (`api:messaging/services/context.py:188-197`) matches the route (`web:src/app/router/paths.ts:59`).

### Faults found (NEW unless an existing blocker ID is cited)

- F17. An expired export is presented as ready. `GET /shared/files/{id}` does not check `expires_at`, so after 7 days the page shows "Your report is ready", auto-starts, and fails on `/url` (404) with a raw error. — evidence `ReportDownloadScreen.tsx:84-107`, `api:documents/services/files.py:213-223`, `api:documents/services/access.py:82-85` — fix: frontend (treat `expiresAt <= now` as the "no longer valid" state); backend optional (410 or an `expired` flag in metadata).
- F18. Report exports, both async and scheduled, are readable by every staff member of the hospital. `may_read` admits any hospital principal for the hospital's own files, and the download guard checks no permission. — evidence `api:documents/services/access.py:65-70`, `ReportDownloadGuard.tsx:37-76` — fix: backend (limit `purpose=export` to `created_by`, or to `reports.view` holders and the schedule's recipients); frontend (check `Reports.view` on this page).
- ENV-01 (existing): emailed download links are relative when `FRONTEND_HOSPITAL_URL` is unset (`api:messaging/services/context.py:83-86,197`). ENV-02 (existing): on the test backend every signed URL points at `storage.fake.local`, so #9 and #11 cannot complete there.

Answers to the audit questions:

- **Can the accountant run reports?** Yes: `RequireAdmin` is a permission gate (`Reports.view`), not an admin-role gate (`RequireAdmin.tsx:18-25`). The only accountant-specific gap is the doctor/department filter options (F12).
- **Can an admin grant or revoke `cash_desk`, `patient_approvals` or `display_devices`?** Yes, through the extra rows under the 10-module grid (`RoleEditor.tsx:224-248`).
- **Does saving the grid drop codes it does not show?** No by design (`gridToPermissionCodes` carries them over), except in the catalogue-timing race (F2).
- **Staff actions match the backend:** the UI uses exactly the backend's four (deactivate, reactivate, reset-password, unlock).
- **Roles:** exactly four, no create, rename or delete; the admin grid is locked on both sides.
- **Expired invitations** are handled via `expires_at` (USR-01). **OTP invite and temporary password** are disabled with an explanation (USR-02).
