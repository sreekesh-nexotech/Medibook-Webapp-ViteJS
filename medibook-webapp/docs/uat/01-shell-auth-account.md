### Faults found (NEW unless an existing blocker ID is cited)

- F1. Ops users are returned to the **Hospital** tab after idle sign-out, session expiry, logout and on a bare `/ops` visit while signed out — evidence `src/app/router/OpsGuard.tsx:27,37`, `src/app/router/useSessionExit.ts:20-23`, `LoginScreen.tsx:68` — impact: re-login attempt goes to `/hospital/auth/login` and fails with "no active hospital access" (and counts against the 5/min identifier limit) — fix (frontend): redirect ops exits to `/auth/login?surface=ops` and let LoginScreen read `surface` like ForgotPasswordScreen does.
- F2. Enter key does not submit the login form (no `<form onSubmit>`) — `LoginScreen.tsx:159-232` — impact: keyboard users / password managers that auto-submit can't sign in with Enter — fix (frontend).
- F3. Lockout UX loses the backend's data: `attempts_remaining` (401) and `locked_until` (423) are never shown — `LoginScreen.tsx:43-51` vs `be:accounts/services/lockout.py:81-86,162-164` — impact: users lock themselves out for 1 h without warning and don't know when/how to recover — fix (frontend).
- F4. Inputs not programmatically labelled; eye toggle unnamed; error banner not announced (`AuthField.tsx:22-33`, `LoginScreen.tsx:178,183`) — impact: screen-reader users — fix (frontend).
- F5. Hard-coded brand-panel statistics presented as facts (`BrandPanel.tsx:6-10`) — fix (frontend/copy).

### Needs API integration or rework

- R1. MFA sign-in step — currently absent — needs SEC-04 backend (TOTP enrol/verify) then a login step for `mfa_challenge`.
- R2. Login toggle — needs `?surface=ops` support (F1).
