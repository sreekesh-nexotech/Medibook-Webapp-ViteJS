# Payments and the cash desk (cash drawer) — UAT audit

> Appendix to [`docs/UAT_REPORT_2026-10-07.md`](../UAT_REPORT_2026-10-07.md). Static, code-level
> audit of web app commit `1ade3ae` against backend commit `b85a87b`; nothing here was run against a live
> backend. Paths under `src/` are in this repository (`medibook-webapp/`); paths under `medibook/` are in the
> Django backend repository; Flutter paths are under `lib/`. **NEW** marks a gap that is not yet logged in
> [`docs/BACKEND_BLOCKERS.md`](../BACKEND_BLOCKERS.md); other IDs (CORE-07, APPT-01, …) refer to that file.
> Status values: OK (wired to an existing endpoint with a matching contract), UI-only (local state only),
> Partial (wired, with a gap a tester will hit), Broken (a real fault), Blocked-backend (the backend lacks
> what the screen needs), Disabled (switched off on purpose, with an explanation), not built (the backend
> has it, the screen does not).

Frontend paths below start `src/…` in the web app (`medibook-webapp/`); backend paths start `medibook/…` in the Django repository.
Seeded roles that reach the screen (`medibook/core/seeds/v1.py:73-100`): admin (everything),
receptionist (`payments.view/add`, `cash_desk.view/add/edit`), accountant (`payments.view/add/del`,
`cash_desk.view`). dept_front_desk has no `payments.view`, so it never reaches the route.

### Faults found (NEW unless an existing blocker ID is cited)

- F1. Refund is offered on a **live** booking. The Appointments drawer offers Refund only when `isPaid && closed` (cancelled/completed/no-show) and routes live bookings through "Cancel & refund". Payments offers it on any captured line — evidence `PaymentsScreen.tsx:608-619` vs `src/features/appointments/presentation/components/AppointmentDrawer.tsx:300-302,406-412`; backend `medibook/appointments/services/desk.py:197-215` (refund never cancels). Impact: a walk-in ends up scheduled + refunded (APPT-01). An **online** booking ends up scheduled + refunded and can never be collected again (`medibook/payments/services/desk.py:54-58`, Q89). Fix: both. Frontend: apply the drawer's rule. That needs the appointment status on the line (backend field) or a per-row fetch. Backend: APPT-01.
- F2. An online (Razorpay) refund leaves the line "Paid" with Refund still offered. A second click fails with 409 "This payment line has already been refunded." — evidence `medibook/payments/services/refunds.py:80-89` (refund stays `requested`, line stays `captured` until the gateway confirms); `PaymentsScreen.tsx:218-220` (refunds are fetched only for `refunded` lines), `:608`. Impact: confusing double action, and no "refund pending" state. Fix: frontend (load refunds for captured lines or show a pending state) + backend (latest refund status on the line).
- F3. The Doctor / Dept column is wrong for appointments outside the selected window — evidence `PaymentsScreen.tsx:173,356-359`. Impact: online prepaid rows usually show a booking ref instead of the doctor. Fix: backend (doctor/department on `HospitalPaymentSerializer`), then frontend.
- F4. The Refunded tab means "captured in window, now refunded", not "refunded in window" — evidence `payments.api.ts:41-51`, `medibook/payments/views/hospital_payment_list.py:41-50`. Impact: today's refunds of older payments are missing from Refunded/Today. Fix: frontend (relabel, or build the tab from `/refunds`, which filters on `requested_at`, `hospital_refund_list.py:15-26`).
- F5. Export failures lose the backend's code and message (Blob body) — evidence `payments.api.ts:90-93`, `toFailure.ts:97-105`. Impact: a 403/400/501 all read as generic errors. Fix: frontend (parse the Blob as JSON on error).
- F6. Export is capped silently at 10,000 rows and is unfriendly for accountants (paise, UTC, enum codes, no doctor/receipt/refund columns) — evidence `medibook/payments/views/hospital_payment_export.py:13-26,108`. Impact: truncated month exports go unnoticed. Fix: backend.
- F7. No date/time column although the list spans up to a month — evidence `PaymentsScreen.tsx:78`. Fix: frontend (`captured_at` is already in the DTO).
- F8. The "refunded today" caption on the **desk** tile includes online refunds — evidence `PaymentsScreen.tsx:188-191,240-242`. Fix: backend (DASH-02: channel on refunds), or relabel in the frontend.
- F9. KPI totals stop silently after 20 pages — evidence `payments.api.ts:38,63-71,103-111`. Fix: frontend (fail loudly like `fetchAllPages`), or backend aggregate totals.
- F10. Refresh does not refresh the cash drawer, reconcile or summary cards — evidence `PaymentsScreen.tsx:300-308`. Fix: frontend.
- F11. On the All tab a failed appointments load is silent, and KPI errors show "—" with no retry — evidence `PaymentsScreen.tsx:365,238`. Fix: frontend.
- F12. Search fires on every keystroke (no debounce) and resets paging — evidence `PaymentsScreen.tsx:429-433`. Fix: frontend.

### Needs API integration or rework

- R1. Payment detail drawer — currently Partial (only refunds read) — needs a drawer over `GET /payments/{id}` (order id, gateway id, reference note, cash session, refunds with status and failure reason).
- R2. Refunds tab — currently Partial — needs a list over `GET /refunds` (status / method / date filters exist) so requested, processing and failed refunds are visible.
- R3. Pending tab and page 1 of All — currently client-side over **every** appointment in the window (an uncapped page loop in `src/features/appointments/infrastructure/data-sources/remote/appointments.api.ts:33-57`) — needs `source=walk_in` server-side, plus `payment_status` many=True on the backend, with server paging.
- R4. Sort headers — currently Partial — wire `sortKeys` → `sort=captured_at|amount_paise`.
- R5. Date range — currently presets only — add a custom from/to picker (the backend already takes any range).
- R6. Receipt no., doctor/department and appointment status on the line — currently Blocked-backend — after the serializer change, show them and use the status for F1.
