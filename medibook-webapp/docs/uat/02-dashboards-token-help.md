### Faults found (NEW unless an existing blocker ID is cited)

- F1. "N patient changes to review" sends the admin to the plain patient list: there is no pending-requests queue in the app, so the alert is a dead end — evidence `AdminDashboardScreen.tsx:243-251`, no caller of `GET /hospital/patient-approvals` (grep: `APPROVALS_PATH` is only used for decisions, `web:…/patients.api.ts:18,95-104`) — admin cannot find what to approve except by opening patients one by one — fix frontend: an approvals list (backend list endpoint exists).
- F2. Appointments KPI counts no-shows while the department chart and Doctor Performance exclude them (`LIVE`) — evidence `AdminDashboardScreen.tsx:173-174`, `api:analytics/services/dashboard.py:80,129` — numbers on one screen disagree — fix backend (part of **DASH-01**: one definition) or frontend (also subtract `by_status.no_show` and say so).
- F3. Alert rows for unpaid walk-ins and approvals open the unfiltered appointment list — evidence `AdminDashboardScreen.tsx:231,240` — tester must re-filter by hand — fix frontend (deep-link filter params on AppointmentsScreen).
- F4. A failed background refetch leaves the previous figures on screen with no stale/error cue (error state only when there is no data at all) — evidence `AdminDashboardScreen.tsx:302` — stale KPIs look current — fix frontend (inline "couldn't refresh" banner using `isError && data`).
- F5. Switching period keeps the old period's numbers under the new labels until the fetch lands (`keepPreviousData`, no `isPlaceholderData` cue) — evidence `useAdminDashboardQuery.ts:20`, `AdminDashboardScreen.tsx:179,210` — brief mislabelled figures — fix frontend.
- F6. Doctor Performance shows "Not on roster" / "—" when the roster or departments request failed, instead of an error — evidence `AdminDashboardScreen.tsx:158-167,420-421` — fix frontend.

### Needs API integration or rework

- R1. Revenue split (online vs desk, by method) and a refunds tile — currently UI-only gap on the admin screen — data already in `GET /hospital/dashboard/admin` (`revenue.by_channel/by_method`); refunds per channel/method need **DASH-02**.
- R2. Patient-change review queue — currently Broken navigation (F1) — wire `GET /api/v1/hospital/patient-approvals` (+ existing approve/reject).
